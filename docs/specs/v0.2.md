# v0.2 Spec — the UI revamp

Status: **Shipped — tagged `v0.2.0` (2026-06-21).** v0.2 is the **UI revamp**
milestone — a deliberately meaningful, non-big-bang release: every screen rebuilt
on a native-feel component system, the single-image media quality suite, the
registration abuse floor, and a time-legible timeline, all on the frozen
[v0.1](mvp-v0.1.md) baseline. What shipped, at what cost: the diary,
[releases/v0.2.md](../releases/v0.2.md).

v0.2 shipped as a bare `v0.2.0` tag; the changelog / release-notes process is a
deferred [ADR-0017](../decisions/adr-0017-versioning-and-releases.md) open item
(decided later, not a release blocker).

Everything in v0.2 is **additive** over v0.1 — all v0.1 wire formats are
unchanged. The one planned wire-format break (multipart-media `attachments[]`)
is deferred to [v0.3](v0.3.md), so v0.2 introduces no protocol breakage at all.

## Headline — UI revamp ([ADR-0023](../decisions/adr-0023-konsta-ui.md))

The whole client moved off shadcn to **Konsta UI** (Tailwind-native iOS/Material
chrome), screen by screen — each a redesign rather than a 1:1 port — with motion
via the View Transitions API. Migration complete (T0–T6); ADR-0023 is Accepted.
Final bundle cost over the pre-migration baseline: **JS +17.0 kB, CSS +8.1 kB
(~+25 kB gzip total)**.

End to end:

- Conversation list, chat (chrome + composer + timeline), settings, the
  unauthenticated flow, and every global overlay are now Konsta
  `Page`/`Navbar`/`List`/`Messages`/`Toast`.
- Native-feel affordances: a per-message `Actions` sheet (edit / destructive
  delete), `Sheet`s and `Dialog`s for destructive flows, an autogrow composer on
  `Messagebar`, frosted iOS surfaces.
- shadcn fully retired (`components/ui/` is empty); the CLI stays available for a
  future bespoke / desktop-only surface.

Full per-screen breakdown (T0–T6, with bundle deltas) lives in the release
diary, [releases/v0.2.md](../releases/v0.2.md), and the ADR.

## Timeline date separators

The timeline is time-legible: a divider precedes the first message of each
viewer-local calendar day, labelled **Today** / **Yesterday** / **14 June** /
**14 June 2025**. Client-only, no protocol surface — pure day arithmetic in
`web/src/lib/timeline.ts` feeding a Konsta `MessagesTitle` row, derived in render
(no lifecycle hook). (Message-list virtualization, its natural pairing, stays
parked until there is evidence of real perf degradation; extended theming moves
to [v0.3](v0.3.md).)

## Media — single-image quality suite (Phase 1, shipped)

The single-image quality work from
[ADR-0022](../decisions/adr-0022-multipart-media.md) landed in full, every piece
**additive on v0.1's single `file`** — optional fields only, no schema break:

| Field on `file` | Meaning |
|---|---|
| `mime` | layout hint (render still sniffs decrypted bytes) |
| `width` / `height` | source dimensions, for zero-layout-shift sizing |
| `optimized` | `false` ⇒ the true original was sent |
| `preview` | a separate encrypted ~50 KB JPEG + its dimensions; omitted below threshold |

Shipped behaviour:

- **Optimized by default** — the stored "full" is downscaled (~2048 px) +
  re-encoded (JPEG q≈0.8); a **"send original"** opt-out in Settings records
  `optimized:false`.
- **EXIF stripped by default** (orientation preserved); image-only, with a
  "keep metadata" opt-in on the original path.
- **Conditional preview** (blur-up, shown first; full fetched on tap) generated
  only above the threshold (~100 KB or ~1024 px on an edge).
- **Compose tray** — stage one attachment (pick / paste / drop) + a companion
  message, sent on an explicit Send ([compose scenario](../scenarios/compose.md)).
- **Lazy-load** — chat images fetch + decrypt on scroll-into-view; non-images
  are click-to-fetch metadata chips.
- **Local media cache** — decrypted previews + below-threshold smalls cached in
  IndexedDB for offline browsing
  ([ADR-0022](../decisions/adr-0022-multipart-media.md) §7).

The album end-state (`file` → `attachments[]`, the one deliberate wire-format
break, with a multi-select composer / per-image captions / grid) is **Phase 2**,
deferred to [v0.3](v0.3.md).

## Registration abuse floor ([ADR-0020](../decisions/adr-0020-registration-proof-of-work.md))

Registration is gated by a **memory-hard Argon2id proof-of-work**: `GET
/v1/register/challenge` issues a single-use nonce + server-set difficulty, the
client computes it in the background while a handle/password is chosen, and
`POST /v1/register` verifies the proof before claiming the handle. Implemented
and enforced (`server/src/pow.rs`); a fail-closed runtime switch
(`DANGEROUSLY_DISABLE_REGISTRATION_POW`) zeroes the difficulty for the e2e suite
only. Rate-limiting and captcha stay deferred (added only if abuse appears) —
see [v0.3](v0.3.md) "Not yet scoped".

## Unread tracking & cross-device read sync ([ADR-0026](../decisions/adr-0026-cross-device-read-markers.md))

"How do I know I have new messages?" Three surfaces, all driven by one piece of
state — a per-conversation **read watermark** (the timestamp of the newest
message seen): a per-row unread count on the chats list, an installed-PWA
**app-icon badge** (`navigator.setAppBadge`, count of conversations with ≥1
unread; feature-detected, no-op where unsupported), and a **`── New ──`
divider** above the first unseen message in a conversation (boundary frozen on
open). Unread counts **incoming** messages only — own sends, self-chat, and
amendments never count. This is **self-state, not a read receipt**: nothing is
ever signalled to the peer, so it does not touch the read-receipts non-goal.

The watermark **syncs across a user's devices**, zero-knowledge — reading on one
device clears the unread on the others, with no fake "new" on the second device.

- _Storage_ — one client-owned blob `users/{uid}/read-markers.json`, AES-256-GCM
  under the **backup key**, in the same versioned envelope as `contacts.json`.
  Body: `{ v: 1, markers: { [conversation_id]: last-read-ms } }`. The server
  stores opaque ciphertext (it never learns which chats exist or where you've
  read) and the layout is one blob — never per-conversation object names that
  would leak the social graph.
- _Merge_ — a monotone CRDT: each watermark only ever advances, so the merge is
  per-conversation `max()`. A device GETs the blob, merges into local by `max()`,
  and PUTs back if it advanced anything; concurrent writers converge with no
  server logic and no locking. The watermark is the *message's own* timestamp, so
  the merge is immune to device clock skew.
- _No new server surface_ — the generic presign + object routes and the existing
  `users/{uid}/*` write authorization already cover the blob. Local read state
  lives on the IndexedDB conversation rows (a v9→v10 migration adds
  `lastReadTimestamp`, backfilled to each row's last-message time so a returning
  user isn't flooded with "all new").
- _Known limitation_ — the app-icon badge is "fresh as of last open": it updates
  only while the app runs (SSE is foreground-only), so a buzz-while-closed refresh
  needs background delivery, deferred to the native track
  ([ADR-0015](../decisions/adr-0015-web-push.md)). The in-app badges and divider
  are always correct on the next open.

Flow + S3 effects: [scenarios/unread-messages.md](../scenarios/unread-messages.md).

## Deferred to v0.3

Moved out to keep v0.2 a focused UI release — full sketches in [v0.3](v0.3.md):

- **Group chats** (the original v0.2 headline) + **chat-URL fragments**
  ([ADR-0024](../decisions/adr-0024-chat-url-fragments.md), accepted together).

- **Media Phase 2 — albums** (`attachments[]`).
- **Extended theming** beyond light/dark.

Already on the **native-apps track** (neither v0.2 nor near-term): background
delivery / push ([ADR-0015](../decisions/adr-0015-web-push.md), Deprecated) and
iOS reach — both live in [evolution/native-apps.md](../evolution/native-apps.md)
and get their own ADR when native is committed.
