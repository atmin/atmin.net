# Rust backend — interop spike (ADR-0018, phase 1)

The de-risking first artifact of the Rust backend experiment: prove the Rust
crates reproduce and verify the Go server's three wire formats against golden
vectors generated by the existing Go + TS code. If they don't — especially the
JCS canonicalization — that's a finding that reshapes the protocol/spec *before*
any handler work. Framework-independent (no Rocket surface yet).

## Spec (what the spike must prove)

Three wire formats must be byte-/semantically interoperable with the running system:

1. **Token** — `base64url(uid "." did "." kv "." base64url(HMAC-SHA256(secret, uid"."did"."kv)))`, unpadded base64url. Rust must produce byte-identical tokens for the same `(secret, uid, did, kv)` **and** parse + verify Go-produced tokens (4-segment only; reject 3-segment legacy).
2. **Auth proof** — Ed25519 over the **JCS-canonical (RFC 8785)** bytes of `{user_id, device_id, timestamp, key_version}`. Rust must (a) canonicalize byte-identically to *both* Go (`gowebpki/jcs`) and TS (`canonicalize`), and (b) verify proofs signed by each.
3. **CBOR archive** — array of envelope objects (`fxamacker/cbor`). Rust (`ciborium`) must decode a Go-marshaled archive to correct values, and a Go-decode of a Rust-marshaled archive must match (semantic equality; byte-identity is a stretch finding).

**Exit:** all three green against golden vectors from Go *and* TS. The JCS battery
(point 2a) is the load-bearing assertion — verify-only could pass for the wrong
reasons, so compare canonical bytes directly.

## Current state

- No Rust server crate exists. Only Rust in-repo is `web/crypto/` (WASM).
- Go formats are live and frozen; the TS client is the production signer of auth proofs.
- No `make` target for a Rust backend; the spike runs via `cargo test` standalone.

### 2. `token` module
- [x] `generate(secret, uid, did, kv) -> String`; `parse(secret, token) -> Result<(uid,did,kv)>`. ([token.rs](../server-rs/src/token.rs))
- [x] Round-trip + rejection tests pass (3-segment, tampered-sig, bad-kv, wrong-secret, garbage encoding). _Rust-internal._
- [x] Assert **byte-identical to Go token vectors** — green ([interop.rs](../server-rs/tests/interop.rs), `token_byte_identity_with_go`): Rust generates the same token bytes Go does, and parses/verifies Go-produced tokens.

### 3. `authproof` module ([authproof.rs](../server-rs/src/authproof.rs))
- [x] `canonicalize(payload) -> Vec<u8>` via `serde_jcs`; **equal to Go _and_ the TS production signer** across the full battery (`jcs_battery_matches_go`, `jcs_battery_matches_ts`, `auth_proof_canonical_matches_ts`), with `go_and_ts_agree` pinning that the two upstreams agree. ⭐ **The gate is fully cleared.** Sole exception: integers > 2⁵³ (Findings).
- [x] `verify(pubkey, payload, sig)` via `ed25519-dalek`; verifies the Go-signed proof and rejects a tampered payload (`auth_proof_*`).
- [ ] Freshness (>5 min) + `key_version < 1` checks — **deferred to phase 3** (handler concern; `verify` here is signature-only by design).

### 4. `cbor` module ([cbor.rs](../server-rs/src/cbor.rs))
- [x] Decode the Go-marshaled archive via `ciborium` (`cbor_decodes_go_archive`): 3 entries, both `msg_id`s in order, text fields intact, and the numbers-as-doubles finding pinned.
- [x] Re-encode in Rust + decode again — semantically stable (`cbor_roundtrip_stable`). Byte-identity **not** pursued: archives aren't canonically encoded (Go map order), so it's neither expected nor required. See Findings.
- [ ] _Optional:_ Rust→Go direction (Go decodes a Rust-emitted archive). Not needed for a replacement; would close the loop for any transition. Deferred — decide at phase wrap.
